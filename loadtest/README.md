# Нагрузочные тесты

Два сценария на k6. Оба запускаются в Docker, ставить k6 локально не нужно.

## Подготовка

```bash
make up          # postgres и redis
RATE_LIMIT_RPS=0 make run
```

`RATE_LIMIT_RPS=0` обязателен: весь нагрузочный трафик идёт с одного адреса, и
лимитер по IP померил бы сам себя, а не сервис.

## `vote.js` — путь настоящего зрителя

Каждая итерация — отдельный человек: своя банка кук, запрос страницы опроса и
один голос. Сценарий сам создаёт опрос, открывает голосование, а в конце
закрывает его и печатает итог.

```bash
make loadtest                                   # 3000 голосов/с, 60 секунд
PEAK_RPS=14000 RAMP=10s HOLD=25s make loadtest  # ближе к потолку
```

Переменные: `PEAK_RPS`, `RAMP`, `HOLD`, `VUS`, `MAX_VUS`, `BASE_URL`, `ADMIN_TOKEN`.

## `hotpath.js` — потолок одной ручки

Только `POST /vote`, без похода за страницей опроса. Все запросы идут без куки,
поэтому почти все голоса отбиваются как повторные — на измерение это не влияет:
путь внутри сервиса тот же самый (разбор запроса, опрос из кэша, один
round-trip в Redis), отличается только последняя строка ответа. Поэтому
`http_req_failed` в этом сценарии близок к 100%, и так и должно быть.

```bash
make seed   # создаст опрос и напечатает poll_id
docker run --rm -i \
  -e BASE_URL=http://host.docker.internal:8080 \
  -e POLL_ID=<poll_id> -e OPTION_ID=<option_id> \
  -e VUS=400 -e DURATION=30s \
  -v $PWD/loadtest:/scripts grafana/k6:latest run /scripts/hotpath.js
```

## Результаты замера

Apple M4 Pro (14 ядер), сервис, PostgreSQL, Redis и сам генератор — всё на одной
машине. Числа занижены: k6 крутится в Docker VM и конкурирует за те же ядра.

| Сценарий | Нагрузка | p50 | p95 | p99 | Ошибки |
|---|---|---|---|---|---|
| Полный путь зрителя | 6 000 голосов/с | 0,49 мс | 0,99 мс | 2,0 мс | 0 |
| Полный путь зрителя | 8 570 голосов/с | 0,77 мс | 1,89 мс | — | 0 |
| Полный путь зрителя | 12 000 голосов/с (24 000 HTTP-запросов/с) | 1,23 мс | 3,57 мс | — | 0 |
| Только `POST /vote` | 45 000 запросов/с | 8,46 мс | 12,79 мс | — | 0 |

За все прогоны сервис принял 1 793 670 голосов. Метрика `vote_flushed_deltas_total`
показала ровно столько же, `vote_flush_errors_total` и `vote_pending_deltas`
остались на нуле: до внешнего счётчика доехал каждый голос.
